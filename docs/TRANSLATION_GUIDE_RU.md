# Гайд по русификации (TRANSLATION_GUIDE_RU)

Как устроена русская локализация этого форка и как в ней работать.

## Архитектура

```
exercises/*.json          # upstream-данные — НЕ ПРАВИТЬ ВРУЧНУЮ
i18n/ru/<id>.json         # русская локализация (сайдкар на упражнение)
i18n/ru/schema.ru.json    # JSON Schema русской записи
scripts/lib/              # глоссарий + движок перевода названий
scripts/draft-ru-names.mjs        # генератор черновиков
scripts/generate-ru-dist.mjs      # merge upstream + RU -> dist/exercises.ru.json
scripts/validate-localization.mjs # валидация (покрытие, дубли, коллизии алиасов)
dist/exercises.ru.json    # генерируемый артефакт (коммитится)
docs/GLOSSARY_RU.md       # канонический глоссарий
```

Почему сайдкары лежат в `i18n/ru/`, а не в `exercises/`: upstream-Makefile
захватывает `exercises/**.json` в `make lint` и `make dist/exercises.json`,
поэтому любой лишний JSON там ломает upstream-пайплайн и CI.

## Формат записи (i18n/ru/<id>.json)

```json
{
  "id": "Barbell_Bench_Press_-_Medium_Grip",
  "locale": "ru",
  "name": "Жим штанги лёжа",
  "aliases": ["жим лёжа", "жим лежа", "bench press"],
  "review_status": "machine_draft",
  "reviewed_at": null,
  "reviewed_by": null,
  "notes": "опциональный комментарий"
}
```

`id` обязан совпадать с upstream id. Английские поля upstream не перезаписываются —
русификация это надстройка, обновления из upstream подтягиваются без потерь.

## Статусы ревью

| Статус | Значение |
|---|---|
| `machine_draft` | перевод создан скриптом/моделью, не проверен человеком |
| `reviewed` | терминология вручную вычитана (обязательны `reviewed_at`, `reviewed_by`) |
| `needs_review` | автоматика не уверена или найдена неоднозначность (см. `notes`) |
| `do_not_translate` | бренд/название оборудования — оставлено как есть |

## Команды

```sh
make draft-ru                 # создать черновики для непереведённых упражнений
node scripts/draft-ru-names.mjs --force   # перезаписать черновики (кроме reviewed)
make validate-ru              # валидация локализации (exit code для CI)
make lint-ru                  # JSON Schema для всех сайдкаров (нужен check-jsonschema)
make dist/exercises.ru.json   # пересобрать dist
```

## Процесс ревью

1. Запустите `node scripts/draft-ru-names.mjs --report` — отчёт по всем названиям,
   `??` помечает `needs_review`.
2. Исправляйте прямо в `i18n/ru/<id>.json`. Если ошибка системная (одинаковый
   термин в нескольких названиях) — сначала добавьте правку в
   `scripts/lib/phrases.mjs` / `overrides.mjs`, затем перегенерируйте `--force`.
   Файлы со статусом `reviewed`/`do_not_translate` скриптом не трогаются.
3. Заполните алиасы: разговорные формы, ё/е-вариант (добавляется автоматически),
   английское название (добавляется автоматически при сборке dist).
4. Переведите `review_status` в `reviewed`, заполните `reviewed_at` и `reviewed_by`.
5. `make validate-ru && make dist/exercises.ru.json` — коммит.

## Добавление нового упражнения из upstream

После `git pull upstream main` новые упражнения появятся в `exercises/`,
`make validate-ru` сообщит о недостающих сайдкарах; создайте их через
`make draft-ru` и вычитайте.

## Импорт в SparkyFitness / Telegram-бот

Используйте `dist/exercises.ru.json`: в каждой записи upstream-поля плюс
`name_ru`, `aliases_ru` (включая английское название в нижнем регистре для
двуязычного поиска) и `review_status`. Не используйте сайдкары напрямую —
они не содержат upstream-данных.

## Как искать

Ищите по `name_ru` **и** по всем элементам `aliases_ru` сразу. При
сопоставлении нормализуйте строку: нижний регистр, `ё → е`, схлопывание
пробелов (та же нормализация, что в `normalizeAlias()` в
`scripts/lib/translate.mjs`).

`aliases_ru` формируются автоматически из четырёх источников:

1. **Выведенные из русского названия**: базовая форма без уточнений в скобках
   («Ягодичный мост со штангой (hip thrust)» → «Ягодичный мост со штангой»),
   короткая форма без инвентаря и позиции («Шраги со штангой» → «Шраги»,
   «Подтягивания с дополнительным весом» → «Подтягивания»);
2. **Ключевые слова движения** по содержанию названия: «жим лёжа», «становая»,
   «присед», «брусья», «тяга блока», «пресс», «трицепс», «махи в стороны» и т.д.
   (правила — `KEYWORD_RULES` в `scripts/lib/translate.mjs`);
3. **Ключевые слова из upstream**: инвентарь (`equipment` → «штанга», «гантели»,
   «гиря», «блок»…) и целевые мышцы (`primaryMuscles` → «грудные», «широчайшие»…)
   — благодаря им русский алиас есть у каждой записи, даже если снаряд не
   упомянут в названии;
4. **Ручные алиасы и ё/е-варианты** из сайдкаров + английское название в нижнем
   регистре (двуязычный поиск).

Общие ключевые слова у многих упражнений («жим», «тяга», «пресс») — норма:
уточнение идёт по остальным алиасам и upstream-полям (`equipment`, `muscles`).
Валидатор считает пересечения предупреждением, а не ошибкой.

Чтобы перегенерировать алиасы после правки правил: `make draft-ru` не трогает
существующие файлы — используйте
`node scripts/draft-ru-names.mjs --force && make dist/exercises.ru.json`.
